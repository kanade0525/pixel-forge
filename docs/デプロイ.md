# デプロイ手順（Cloudflare Pages）

private リポジトリのまま、無料で公開できます。GitHub との連携（初回のみ）はブラウザで行います。

## 前提（リポジトリ側は準備済み）

- ビルドコマンド：`npm run build`
- 出力ディレクトリ：`dist`
- Node バージョン：`.nvmrc` に `22` を指定済み
- セキュリティヘッダ／CSP：`public/_headers`（ビルド時に `dist/_headers` へコピーされ、Cloudflare が本物のHTTPヘッダとして配信）

## 手順

1. [Cloudflare ダッシュボード](https://dash.cloudflare.com/) にログイン（無料アカウントでOK）。
2. **Workers & Pages → Create → Pages → Connect to Git**。
3. GitHub を連携し、リポジトリ **`kanade0525/pixel-forge`** を選択（private のままでOK）。
4. ビルド設定を入力：
   - **Framework preset**：`Vite`（無ければ None）
   - **Build command**：`npm run build`
   - **Build output directory**：`dist`
   - **Environment variables**：`NODE_VERSION` = `22`（`.nvmrc` があれば省略可）
5. **Save and Deploy**。数分で `https://pixel-forge-xxxx.pages.dev` が発行されます。
6. 以降、`main` に push するたびに自動で再ビルド・再デプロイされます。

## 独自ドメイン（任意）

Pages のプロジェクト → **Custom domains** から独自ドメインを割り当てられます（DNSをCloudflare管理にすると簡単）。

## 注意

- 本ツールはクライアント完結のため、配信される JS は誰でも閲覧可能です（client-side app の仕様）。private リポジトリで守れるのはソース履歴・未ビルドのソースです。
- CSP は `connect-src 'none'`（外部通信ゼロ）。もし Cloudflare Web Analytics などの外部スクリプトを後から入れる場合は、CSP（`public/_headers` と `vite.config.ts` の注入）を対応する形に緩める必要があります。

## 他ホストの場合

- **Netlify**：Build command `npm run build` / Publish directory `dist`。`_headers` はそのまま有効。
- **GitHub Pages（public化 or 有料）**：`vite.config.ts` に `base: '/pixel-forge/'` を追加し、GitHub Actions でビルド→Pagesへデプロイ。`_headers` は無効（Pagesはカスタムヘッダ非対応）なので CSP はメタタグ側で担保。
